# Scenario and trace schema

`scenario.rs` defines the framework-neutral version-1 scene and input contract shared by Rust, Swift, and TypeScript comparison adapters.

`ScenarioSpec` identifies frozen fixture, asset, font, style, layout, phase, metric, parity, and fairness inputs. Style tokens and layout assertions are content-addressed artifacts rather than unverified paths. The fairness contract records the logical viewport, baseline visible semantic-role counts, event tolerances, locale, timezone, direction, and the invariant that animation and mutation work follows elapsed monotonic time instead of rendered-frame count.

Each `ParityCheckpoint` binds a stable checkpoint ID to a declared phase and optional integer virtual-clock offset. It content-addresses the expected state, normalized accessibility fingerprint, optional promoted runtime geometry, and canonical screenshot, and freezes the visible semantic-role counts at that checkpoint. Optional `recapture_status` is a canonical lowercase kebab-case control-plane marker: correctness acquisition may replace that stale reference, but qualification and measured acquisition must reject the selected scenario before application launch. Runtime geometry is optional for existing scenario packs; release promotion supplies it so resize checkpoints and profile-specific roots remain content-addressed per checkpoint instead of being forced through one scene-wide layout root.

`TraceEvent` stores integer microsecond offsets and integer millionths for normalized coordinates. Its finite `TraceOperation` set covers pointer, wheel, keyboard, text/IME, focus, surface, data, navigation, lifecycle, resource-arrival, and pressure events. Every phase trace is an `ArtifactIdentity`, not a bare path. This avoids floating-point or cross-language PRNG differences during acquisition.

`AssetManifest` content-addresses every asset byte by a stable semantic role, media type, and color space. Its optional `InlineTextAtlas` freezes one logical grid plus ordered content-addressed raster variants. Each `InlineTextAtlasVariant` declares its artifact role, exact physical dimensions, and physical em size; each `InlineTextAsset` preserves one exact grapheme, grid cell, and integer-millionths advance, baseline offset, width, and height. The committed variants retain the 128-pixel source cells and add exact-density 45- and 39-pixel cells for canonical 15- and 13-point text at 3x. This prevents emoji or symbol fallback and runtime minification from silently changing pixels while retaining the original fixture string as semantics and accessibility text. `FontPackManifest` content-addresses each font and its license while retaining an HTTPS GitHub repository, full lowercase commit object ID, and repository-relative source path. Each `FontPackFile` carries an ordered, complete `variation_axes` list. Public `FontVariationAxis { tag: String, value_millionths: i64 }` stores one printable four-byte OpenType tag and its deterministic coordinate without JSON floating-point ambiguity. `canonical_font_pack_json` freezes its reviewed key order and bytes. `validate_scenario_artifacts` resolves every fixture, asset manifest/member, font-pack manifest/member/license, style, layout, checkpoint geometry, screenshot, and trace beneath one canonical versioned spec root. It rejects absolute paths, traversal components, symlink escapes, missing files, hash mismatches, malformed asset or font manifests, malformed trace JSON, and invalid trace semantics.

Validation rejects missing or malformed font/style/layout/trace/checkpoint identities, duplicate scene roles, noncanonical JSON/PNG artifact types, incomplete locale or zero trace tolerances, checkpoint IDs that repeat, checkpoints bound to unknown phases, virtual-clock offsets beyond a declared phase duration, empty or noncanonical recapture markers, empty checkpoint role contracts, and roles that the scene does not declare. The committed `benchmarks/comparative/specs/v1/fixtures/scenario-v1.json` is a schema fixture, not an executable campaign selection. Runnable scenario manifests must pass both structural and on-disk artifact validation; placeholder identities cannot satisfy acquisition.

Font axis order is the font's `fvar` axis-record order, not alphabetical order. The v1 pack pins Latin and Arabic to `wght=400`, `wdth=100`, and Simplified CJK to `wght=400`, represented as `400000000` and `100000000` millionths. Adapters consume the ordered values directly; missing, extra, reordered, duplicate, non-printable, or out-of-range axes are invalid.

The v1 inline-text atlas contains the ten feed/chat grapheme clusters omitted by the pinned text fonts. Its pixels come from the closest declared content-addressed raster variant; no adapter may replace an entry with a system emoji or symbol.
