# Apple benchmark campaign executor

`BenchmarkCampaignExecutor` is the first real packed Apple phase driver. It validates the exact bundled root-plan hash, verifies the root plan's acquisition, budget, and six scenario-manifest identities, and loads each selected scenario through the exact manifest identity declared by that root before materializing its nested artifacts and traces. The invocation SHA-256 names `plans/apple-pr.json`, never the acquisition leaf. Execution uses one shared native-rate `CADisplayLink` with `CAFrameRateRange.default`, advances logical work by elapsed continuous time, records the fixed common telemetry subset, and flushes binary telemetry, complete event-availability coverage, and generation-bound complete/ACK artifacts only after all measured scopes terminate. The native range is mandatory on macOS: an 80 Hz minimum can suppress every callback when the active display cannot satisfy it.

The executor records `readyToInput` at the exact durable-ready clock boundary. It validates paired common scopes and refuses samples for unavailable or external-only event kinds before writing completion evidence. Presentation stays in the external frame-lifetime correlation path; `displayOpportunity` remains only a callback opportunity. On diagnostic passes, the comparison-only Oxide runtime timestamps render preparation, encode begin/end, and the submit call, while the Oxide macOS adapter timestamps the real `nextDrawable` wait. Initial pre-ready frames are excluded when their stage timestamps precede the ring's ready boundary. Completed command-buffer durations use `gpuDuration`, sampled after completion. Clock-aligned GPU start/end, framework-internal AppKit stages, layout attribution, inflight depth, and update backlog remain explicitly unavailable instead of appearing as zeros.

Measured macOS trace replay first compiles every expanded schedule through the trusted-input capability contract. Before the controlled start barrier, it persists the immutable request descriptors and prepares the session-global command table. User commands pause schedule consumption and use Darwin readiness/request signals plus an in-memory typed controller receipt; already-due actions remain deferred until the exact foreground receipt validates. Only explicitly declared application stimuli reach `adapter.apply`. The measured waiting/dispatch path performs no artifact reads, JSON work, hashing, filesystem probes, or writes. Once all measured scenarios end, the executor requests the controller flush, persists buffered application receipts, and only then materializes telemetry and completion evidence. See [macOS trusted-input control](macos_trusted_input_control.md).

Timed comparison passes also emit comparison-only `InputReceived`, `VisualGeneration`, and `DisplayOpportunity` signposts under the `com.oxide.comparison` / `Presentation` stream. Every marker carries the scenario index and logical generation, allowing the external controller to correlate input, app visual generation, display opportunity, and compositor presentation inside the same Instruments trace. Correctness mode emits none of these timing markers.

The executor has a separate correctness mode. It never starts a display link and never uses elapsed wall time: it drains the frozen scheduler in timestamp/priority order, applies every trace event, captures every parity checkpoint, and rejects a missing, duplicated, reordered, state-mismatched, accessibility-mismatched, or role-count-mismatched checkpoint. Trace-only phases derive their duration from their latest trace/checkpoint timestamp, which preserves the startup warm-resume event at 1 microsecond instead of rejecting it as a zero-duration phase. The non-launch correctness execution follows the explicit reset-segment order (`core-interaction`, `scroll-damage`, `media-text-warm`); the launch pack has no reset.

Every correctness checkpoint stores canonical actual state/accessibility JSON, actual hashes, expected frozen hashes, actual visible-role counts, and an actual PNG when the adapter supports capture. On macOS it also requires a `BenchmarkMacOSCorrectnessGeometryCapture` adapter and persists `geometry.actual.json` from the live root bounds under the shared canonical profile; absence fails the checkpoint. An adapter that exposes a raw platform accessibility tree stores it as a distinct hash-bound artifact; this evidence never replaces the normalized cross-framework fingerprint. Each checkpoint capture runs inside an explicit autorelease pool so screenshot and AppKit/UIKit/Core Graphics temporaries are released before the next checkpoint. Screenshot status is `host-static-calibrated-oxide-native-pair-pending`, never pass. Static acceptance requires exact cross-framework state/accessibility/geometry bytes, exact canonical screenshot dimensions, frozen full-frame perceptual thresholds, and the localized voxel guard. Exact RGB differences remain persisted diagnostics. Reset sentinel evidence stores segment membership plus canonical before/after state and accessibility artifacts and requires exact equality; it contains no footprint measurement. The correctness complete envelope carries zero telemetry bytes and explicitly declares that it makes no timing claim.

For the non-launch pack, the executor quiesces the first warmed prepared scene once and freezes one physical footprint as the pack baseline. Correctness first prepares every selected scenario and drains a fresh `BenchmarkPhaseSchedule`, applying trace events and captures in the same timestamp/priority order as the real replay before teardown. This makes the prewarm interaction and capture sequence identical to the mandatory correctness workload, including repeated time-offset checkpoints. It then prepares the real first scene and converges the screenshot path: up to six further captures must produce two successive physical-footprint samples within 5%, otherwise the campaign fails before execution. After the durable ready artifact has initialized the same JSON/hash/write control path used by evidence, the executor samples the fixed pack-wide baseline. This represents all infrastructure necessarily live before execution without ratcheting during scenarios; presentation never performs the capture prewarm or inherits its memory. After every scenario teardown, the executor invokes an optional adapter-owned retirement drain before allocator pressure relief or footprint sampling. AppKit uses that boundary for six complete default-mode main-run-loop turns because framework cleanup can outlive already-released app-owned scene objects; UIKit and Oxide do not add work when they do not implement the protocol. At the end of each declared segment the executor pauses the shared display link, quiesces before teardown, releases adapter-owned scene resources, and asks Darwin's allocator to return unused pages before waiting no longer than the manifest reset deadline for physical footprint to return to at most 105% of the fixed baseline. The pressure-relief call cannot release live UIKit or adapter objects; it prevents free allocator pages left by screenshot encoding from masquerading as retained scene ownership. Pausing prevents deadline RunLoop polling from reentering a torn-down adapter; the link resumes only after successful recovery. Recovery never samples a new baseline, so later segments cannot ratchet. A timeout hard-fails the remaining pack before another segment is prepared. Successful recovery is persisted as a distinct typed record containing segment, fixed baseline, observation, limit, deadline, and validation. Presentation telemetry emits paired quiescence/reset-complete records; correctness stays telemetry-free.

UIKit keeps one stable window root and mounts each scenario in a detachable child viewport. Teardown removes the benchmark child controller and view from both containment and the visible hierarchy, leaves the stable root blank, releases fixture/assets/scene ownership, and flushes the layer transaction before the recovery sample. This avoids UIKit retaining outgoing root-controller transition state across packed scenarios. Correctness navigation uses immediate route/modal updates because its scheduler is virtual; presentation passes continue to use native UIKit transitions.
The image scene also clears the image-view image and layer contents, scene decoded-image handle, and prepared-asset decoded-source cache before detachment. The full 4096×3072 source is decoded into an explicitly owned sRGB bitmap so teardown has a concrete owner to release rather than depending on `UIImage(data:)`/ImageIO display-cache lifetime.

Oxide rendering is driven by that same shared callback through `BenchmarkFrameDrivenAdapter`; the Oxide adapter no longer owns a second display link. UIKit remains natively transaction-driven. Immutable fixtures, fonts, and images are retained across model/view resets.

The current executor labels its input scope `direct-callback-diagnostic` and refuses to present the result as claim-bearing. The raw correlation markers are present, but OS-injected input plus parsed and calibrated common Core Animation presentation attribution remain required before the minimal-presentation primary can be enabled.

## Generic campaign execution

When `BenchmarkCampaignInvocation.planArtifact` is present, preparation uses the content-addressed generic plan instead of the Apple/PR acquisition. It validates the full plan and scenario closure, selects the requested pass/pack, builds schedules directly from the scenario manifests with no invented setup time, sizes the fixed telemetry ring from their aggregate declared duration, configures pass-gated renderer diagnostics, prepares the first scene, and emits the same durable ready/complete envelope path. This path runs correctness, primary-presentation, idle, endurance, energy, and the declared attribution workloads. Packs provide ordering only; each scene is still torn down before the next scene is prepared.

Generic canonical-launch remains routed to `MacOSCanonicalLaunchExecutor` by the app composition root and is not accepted by the packed executor. The current controller does not yet provide the generic plan path or materialized plan bytes, so end-to-end launch of nightly/release tiers remains gated at controller invocation construction rather than at Swift plan decoding or workload execution.
