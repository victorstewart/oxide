# Apple benchmark campaign contract

> **Extended diagnostic path:** this 906-second campaign is not a prerequisite
> for visual equivalence or output-ready benchmarking. The active fast lane is
> defined by `.tasks/plan-production-comparison-benchmarks.md`; invoke this
> campaign only for an explicitly requested claim-complete investigation.

`Shared/Foundation/BenchmarkCampaign.swift` treats `plans/apple-pr.json` as the controller-supplied plan identity. Its exact raw SHA-256 binds the canonical Apple/PR identity, the acquisition and budget artifacts, and the ordered six scenario manifests. Preparation verifies every declared leaf hash before nested scenario loading, then decodes the acquisition only through its declared identity and requires its selected-scenario order to equal the root plan. A scenario-manifest byte change therefore invalidates the campaign even when its relative path is unchanged. Acquisition validation freezes one build-for-testing, the three named non-launch reset segments, the dynamic and launch pack arithmetic, exactly four controller chunks, the two public XCTest methods, no lean replay, four artifact pulls, and the 906-second hard plan. Host materialization derives the paired-execution seed from the exact plan SHA-256 and uses benchmark-spec's frozen xorshift64 algorithm to choose one deterministic ABBA or BAAB block per four pairs; every side artifact carries the resulting `ab` or `ba` session identity expected by the analyzer.

The correctness chunk deliberately has no timed pair indices. The controller expands its frozen `pr-non-launch` and `pr-launch` pack list into two generation-distinct untimed execution indices and launches both comparator applications for both packs. `-oxide-compare-pack` is mandatory for the correctness pass, while minimal-presentation and canonical-launch remain pinned to their single valid pack. Every ready, start, complete, and failure signal remains generation-qualified, so per-app-container fallback cannot release a new execution with a stale notification from the preceding app or pack.

The same prepared-app path now accepts the isolated `canonical-launch` pass. Its durable ready envelope records the app's `mach_continuous_time` timestamp and timebase next to the generation and scenario identity before emitting the generation-specific ready signal. This makes controller launch-to-ready a reproducible diagnostic on one device clock; it remains explicitly unavailable for a launch headline until the common Core Animation trace attributes the corresponding presentation.

`BenchmarkCampaignEnvelope` is the post-execution control artifact. Every macOS envelope hash-binds an app-reported surface receipt containing logical window/viewport geometry, backing pixels and scale, insets, final color/alpha/sample contract, compositor scaling, target refresh, observed display-link refresh, and record-only implementation/internal format. Timed diagnostic passes also bind the app telemetry bytes, the complete event-availability coverage artifact, timebase, side/pair/chunk/generation, scenario record ranges, logical-update totals, injection scope, and prior host checkpoint. Correctness envelopes instead declare `timingClaim = none-correctness-untimed`, carry zero telemetry bytes and no coverage artifact, and bind pack identity, every checkpoint artifact/hash, reset-sentinel equality proofs, and distinct post-segment recovery proofs. `BenchmarkResetRecoveryEvidence` records the fixed warmed pack baseline, recovered physical footprint, 105% limit, manifest deadline, and validation for one declared segment. The predecessor is host-checkpoint authority; per-app containers cannot safely make the native app depend on an unreadable raw Oxide-container file during one controller acquisition.

Checkpoint validation parses and canonically re-encodes both the adapter-produced state and accessibility JSON before comparing them with the frozen artifacts, then separately requires an exact unique role-to-count map. Actual canonical JSON is durably stored for every checkpoint. When an adapter provides `BenchmarkPreviewCapture`, its actual PNG and SHA-256 are stored too, but Swift does not claim visual acceptance: each screenshot remains explicitly `host-static-calibrated-oxide-native-pair-pending` until the host pairs the Oxide and native captures. Host admission requires exact state/accessibility equality, exact canonical dimensions, frozen full-frame SSIM/differing-pixel/Delta-E thresholds, and the localized voxel guard; exact RGB differences remain diagnostics. The three named non-launch reset segments each invoke the adapter reset path once and persist before/after state and accessibility sentinel evidence; those canonical artifacts and role counts must remain identical. Memory recovery occurs separately after the segment finishes and always compares with the one fixed pack baseline.

Measured telemetry uses the fixed binary format from `BenchmarkTelemetryRing`. JSON encoding and durable file writes occur only after measurement.

The separate `BenchmarkReleaseCandidateCaptureExecutor` never enters a measured campaign. It loads only the five screenshot-free candidates through the explicit capture loader, replays their virtual-time schedules, validates frozen state/accessibility/role counts, and writes live geometry and PNG evidence beneath `native.evidence` or `oxide.evidence`. Its completion receipt binds the capture-plan SHA-256, exact scenario order, 18-checkpoint count, and the `none-correctness-untimed` claim. Both applications terminate immediately after the capture completes.

## Generic nightly, release, and audit plans

The same comparison-only Swift unit now decodes the benchmark-spec `AppleCampaignPlanSpec` used by macOS nightly, release-core, claim-complete, extended, and full-attribution campaigns. A generic invocation supplies `-oxide-compare-plan-path plans/<name>.json`; the existing `-oxide-compare-plan-sha` is the exact raw SHA-256 for that file. Omitting the path retains the frozen Apple/PR loader and pack rules unchanged.

Generic validation rejects the PR tier, a non-Apple identity, a plan/budget-id mismatch, duplicate or empty scenario/pack/pass ids, a noncanonical scenario path, a missing scenario artifact identity, an invalid artifact hash, unknown pack/scenario references, invalid role-specific pass ids, collector/launch-class drift, incomplete or multiply-owned budget components, and tier matrix drift. Loading then reads every declared scenario through its content address and validates the complete nested scenario artifact closure. A plan with even one absent release candidate is therefore not runnable.

`selectAppleCampaignExecution` resolves one declared pass and, when required, one declared pack. Multi-pack `primary-presentation` must name a pack. `idle`, `endurance`, and `canonical-launch` have one unambiguous pack. Correctness, energy, attribution-time-profiler, attribution-system-trace, common-gpu, attribution-physical-footprint, and full-attribution select their explicit scenario lists without accepting a fabricated pack. The selection preserves pack order and rejects a pack containing work outside the pass.

The app-side command-line decoder now understands those generic pass ids and records the plan artifact in `BenchmarkCampaignInvocation`. The macOS controller still materializes only the frozen Apple/PR invocation and does not yet persist a generic materialized plan or pass `-oxide-compare-plan-path`; that controller handoff is the remaining boundary before the new tiers can launch from `xtask compare-ui run`.
