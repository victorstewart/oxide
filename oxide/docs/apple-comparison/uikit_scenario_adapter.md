# UIKit PR scenario adapter

`UIKit-iOS/UIKitScenarioAdapter.swift` implements the common Apple scenario lifecycle for all six PR workloads. It reads only validated framework-neutral fixture bytes, verifies and registers every pinned font member and license before scene construction, and receives Latin, Arabic, and CJK fonts from the shared committed-file CoreText catalog rather than looking up named faces. Every point size used by the six scenes is created with the manifest variation axes during preparation; no measured render path resizes a font. Graphemes outside that pack use the verified inline-text atlas rather than platform emoji or symbol fallback. UIKit owns production objects rather than benchmark screenshots.

Every scene is mounted inside an exact centered 390x844 logical viewport. This keeps the 1170x2532 backing contract on the 3x physical iPhone independent of the surrounding device model's full-screen logical size; the host cannot silently expose more or fewer rows because a Pro Max window is larger.

- The dashboard constructs the frozen 300 semantic nodes, including 32 rounded shadow cards, 176 labels, 64 image views sampling the pinned atlas, 24 controls, and four material blur regions. Leaf and 10% mutations update the existing hierarchy.
- The feed uses `UITableView` reuse for all 2,000 variable-height rows and a reusable native card cell with the frozen 4-point row inset, rounded surface/shadow, clipped 48-point atlas thumbnail, two real text labels, and standalone favorite control. It retains deterministic multilingual fixture strings, exact 24-by-24 crops from the hash-verified shared atlas, cached attributed image runs for pinned symbols/emoji, scroll state, one favorite mutation, and the 20-row prepend.
- The chat uses ten reusable native cells over the 5,000-message fixture. Every bubble installs the same circular corner and zero-blur, 2-point-offset shadow as the shared style, with a frozen shadow path refreshed from the final cell bounds.
- Navigation uses a normal navigation controller, list reuse, detail push, form-sheet modal, dismiss/back transitions, four canonical cycles, and cancel restoration. Presentation passes retain native UIKit animation; the untimed virtual-clock correctness pass applies the same route/modal states without starting real-time UIKit transition coordinators.
- Startup uses `UICollectionView` reuse over the exact 24 card records and 24 KiB payload. Its 2-column, 3-row viewport presents exactly six initial cards and six atlas images alongside the frozen header, navigation row, and primary control. Foreground, background, and fresh-install resource events update scene lifecycle state without changing the visible contract.
- Chat uses an idiomatic reusable `UITableView` for all 5,000 base messages and the exact ten-message viewport. A deterministic variable-height cycle totals exactly 700 points per ten sequential rows, so prepend and 10 Hz append operations preserve ten visible messages. Pinned atlas avatars, Noto script selection, `UITextView.insertText` for 100-character typing and the 10 KiB paste, and UTF-8 selection replacement cover every committed trace operation without system-keyboard UI entering the renderer comparison.
- Image starts with the exact 384 by 288 thumbnail, decodes the hash-verified 4096 by 3072 PNG into an explicitly owned 8-bit sRGB bitmap at the decode trace event, and promotes it on the first-visible event. The framework-neutral pointer trace feeds a UIKit-owned active-pointer state machine; the scene applies ordinary `CGAffineTransform` translation and scale to its clipped `UIImageView`, including one-finger pan and two-pointer pinch handoff.

## Retained asset lifetime

Preparation constructs one `UIKitPreparedAssets` object per prepared scenario. It owns the decoded thumbnail atlas image and all 128 thumbnail crops, every decoded inline-text raster variant, one `UIKitPreparedInlineText` cache with variant-selected cell crops and attributed strings for unique feed/chat fixture values, verified source PNG bytes when the image scenario needs them, the decoded thumbnail, and the explicitly owned full-source bitmap after the first decode event. The attachment bounds apply the frozen advance, baseline offset, width, and height at the active point size. The original fixture string remains the accessibility label. `reset` calls the existing scene's in-place seed restoration without replacing its controller, root view, table/collection view, fixture, or prepared assets. Startup clears lifecycle counters and scroll; dashboard restores seeded text/colors; feed and chat restore retained seed arrays plus scroll, focus, selection, and editor state; navigation dismisses transient controllers and returns to its retained root list; image restores the thumbnail and clears gesture/resource-presentation state while the prepared asset cache remains warm. Full `teardown` clears the image view and layer backing, releases the decoded bitmap/source cache, and releases the prepared object.

Inline attachments are prepared from every declared content-addressed raster variant. UIKit selects the closest physical em to `font.pointSize * UIScreen.main.scale`; the canonical 15- and 13-point labels therefore use the 45- and 39-pixel variants at 1:1 with no runtime minification.

This lifetime shape is also the Oxide parity boundary: the Rust host should retain every inline-atlas variant texture handle, one full-source resource/handle, and one thumbnail resource/handle across canonical scene resets, while resetting route, message, input, pan, pinch, and visibility state. A reset that re-reads or re-decodes bytes on only one side is not apples-to-apples.

## Contract and failure behavior

The adapter decodes the new startup/chat/image fixture shapes once before scene installation and rejects wrong schema identities, counts, payload sizes, image dimensions/formats/color space, gesture constants, and trace targets. The shared loader verifies every content hash before UIKit sees the bytes. Scene role counts are the exact checkpoint contracts: startup `1/1/6/6/1`, chat `1/10/10/1/1`, and image `1/1/1` in manifest order.

All scene allocations, fixture decoding, atlas slicing, font registration and axis application, and thumbnail loading happen before measured trace dispatch. Reset may ask existing UIKit lists to reload their restored seed data, but it does not allocate a replacement scene or controller tree. Chat performs only the product operation requested by each event: insert/prepend/append/reload the affected reusable rows or insert text through `UITextView`. Image decoding intentionally occurs at the decode event; later resets reuse the retained resource as required by the warm-resource contract.

The adapter returns its live scene model, semantic accessibility nodes, observed role counts, and cleanup through the same `prepare`, `reset`, `apply`, `checkpoint`, and `teardown` surface as the Oxide adapter. Models cover lifecycle visibility, mutation counts, deterministic scroll position, message/focus state, navigation visibility, and fixed-point image transforms. Side-specific raw UIKit class hierarchy capture remains outside exact cross-framework comparison because the evidence envelope currently has no non-compared platform-tree field. Comparator acceptance, presentation attribution, and physical-device campaign evidence remain separate gates.

Static preview capture renders the settled UIKit layer tree directly into the canonical opaque standard-range 3x bitmap. This excludes display-compositor dithering and other presentation-only filtering from the static contract, matching Oxide's offscreen Metal target boundary. It does not flatten, substitute, or replay a screenshot: UIKit still renders its live production layer tree for every captured checkpoint. The resulting normalized sRGB8 pixels must match Oxide exactly; masks, SSIM, Delta-E, and tolerances remain diagnostic only.

Every rounded UIKit layer explicitly selects `CALayerCornerCurve.circular`, matching the shared style contract and the materializer's circular containment rule. Platform-selected automatic or continuous/squircle corners are invalid because they can change static coverage across OS versions without changing the scenario manifest.

## Verification

The UIKit production target compiles in unsigned Release mode with:

```text
xcodebuild -project host/apple-comparison/AppleComparison.xcodeproj -scheme UIKitBenchIOS -configuration Release -sdk iphoneos CODE_SIGNING_ALLOWED=NO build
```

This proves the checked-in source compiles against the iOS 26.5 SDK without editing the generated Xcode project. Runtime state, exact static pixels, accessibility, and physical-device presentation evidence remain separate campaign gates.

For real-host visual development only, both Apple apps accept `-oxide-compare-preview -oxide-compare-scenario <id> -oxide-compare-preview-generation <64-lowercase-hex>`. This bypasses acquisition and emits no telemetry evidence. After successful resource validation, font registration, scene preparation, layout, initial checkpointing, and PNG capture, each durably writes `Documents/ComparisonPreview/preview.png`, then writes `complete.json` last. The completion diagnostic binds the requested generation, bundle/scenario identities, observed role counts, and captured PNG SHA-256; a host must reject a generation or PNG hash mismatch as stale evidence. OxideBenchIOS uses its Rust/Oxide adapter and cannot silently render the UIKit scene under the Oxide bundle ID.
