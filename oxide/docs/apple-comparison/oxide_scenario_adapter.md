# Oxide Apple scenario adapters

`Oxide-iOS/OxideScenarioAdapter.swift` mounts the Objective-C `MetalView` supplied by the normal `oxide-host-ios` static library and submits through its ordinary `CAMetalLayer`, Rust router, draw-list, and Metal renderer path. The view is fixed to the contract's centered 390 by 844 logical viewport with a 1170 by 2532 drawable on the 3x device.

Preparation asks Rust to revalidate the complete six-scenario Apple PR pack, decode and upload the pinned immutable thumbnail atlas once, register the three pinned Noto fonts, parse canonical traces before measurement, and prepare the requested scene. Swift maps each decoded event to its preloaded phase/index pair, so measured dispatch does not serialize or parse JSON. Reset recreates model state while retaining the uploaded texture and font resources.

The image scenario retains the exact compressed source bytes during setup but defers the 4096 by 3072 PNG decode and immutable Metal texture creation to the canonical `image:decoded` and `image:texture` trace events. The decoded bytes and uploaded handle then remain resident across reset, matching UIKit's retained prepared-asset lifetime for warm segments. The deterministic thumbnail is decoded and uploaded during setup because it is the initial visible state.

The adapter exposes Rust-observed role counts and drives elapsed-time transitions from the display link. For correctness checkpoints it requests live state and accessibility JSON from the Rust scene through a two-call length/copy ABI. Swift does not reconstruct Oxide state from frozen checkpoint metadata. Serialization occurs only on explicit checkpoint requests, outside display ticks and measured presentation paths. Screenshot capture, attributed-presentation, and telemetry acquisition remain separate evidence.

The macOS adapter enables direct renderer diagnostics only for the comparison-only `common-gpu` and `full-attribution` passes. The ordinary correctness, lean presentation, and launch binaries keep the diagnostics path disabled. Correctness PNG dimensions and geometry evidence share `BenchmarkMacOSCorrectnessCaptureProfile.canonical`; geometry comes from the installed Metal view's live bounds plus the actual encoded draw-list primitive and glyph-run bounds, and both offscreen preparation and snapshot capture consume the profile scale instead of duplicating a literal. This evidence proves renderer-input geometry rather than semantic role/ID mapping, which remains a separate admission requirement. The comparison runtime reads the production Metal renderer's completed command-buffer duration and existing encode, draw, and damage counters after submission; it does not add timing work to the production renderer. Records carry the renderer frame ID, and the adapter fails the acquisition if observed submission or completion IDs become noncontiguous instead of silently reducing the GPU distribution. These Metal values are implementation diagnostics. They do not replace the identically scoped common device/system GPU collector required for an Oxide-versus-AppKit headline comparison.
