# macOS acquisition validity

## Purpose

`acquisition_validity` is comparison-controller code, outside every production Oxide and AppKit artifact. A full macOS campaign records environment snapshots at both campaign endpoints and immediately before every pair, derives metric-family-aware eligibility gates, and persists `acquisition.validity.json` before writing `campaign.complete.json`.

## Evidence contract

The artifact binds the run, source plan, build manifest, and exact expected pair count. Each endpoint and pre-pair snapshot records hashed raw observations for thermal state, display topology, logical and backing display dimensions, scale, rotation, mirroring, connection/display type, observed refresh, and power source. Every primary app session now writes a content-addressed surface receipt; the completion envelope binds it and the controller reopens, rehashes, and validates its session identity. Window/viewport size, backing pixels and scale, insets, final color format/space, alpha, sample count, compositor scaling, target-refresh policy, and target refresh compare exactly. Observed refresh uses the schema-owned 0.5% relative tolerance. Surface implementation and internal format remain required recorded evidence but are `record_only`, because AppKit does not expose WindowServer's internal format symmetrically with Oxide's CAMetalLayer. Values that macOS does not expose through a supported read-only API likewise remain typed `unavailable`; the controller does not infer fan RPM, brightness/nits, True Tone, Night Shift, notification/background-sync state, active screen recording, room temperature, color profile, EDR headroom, or GPU load from private defaults or undocumented registry keys.

Each pre-pair observation runs the bounded `top` contract for eleven 1 Hz samples, discards the invalid first CPU interval, and reduces the remaining exact ten seconds. The raw output is capped at 64 MiB. The report records total median and peak CPU, per-process median/peak attribution, cumulative idle-wakeup deltas, and a raw SHA-256. Global background admission uses the frozen Section 9 limits: median CPU no greater than 5% of one core, peak CPU no greater than 20%, and no more than five wakeups per second. The pre-pair identity set must exactly match the campaign's chunk/pass/pack/pair set. A stable display requires exactly one awake, online main display with unchanged physical surface fields; power must remain AC and thermal state nominal.

`environmentPolicies` freezes every field to `exact`, `tolerance`, or `record_only`, with units and numeric bounds. Measured luminance uses `max(5 nits, 2%)`; room temperature uses 22 C +/- 2 C; unrelated GPU uses at most 1% active when available. Unsupported unrelated GPU makes `comparableGpuClaimsAvailable` false without invalidating CPU, memory, startup, or latency claims. Missing room temperature makes `shortRunEnergyEquivalenceAvailable` false, and missing luminance or display controls makes `displaySensitiveClaimsAvailable` false. Fan state is record-only. Reduce Motion, notifications, background sync, and screen recording are reported through `interactionEnvironmentClaimsAvailable`. These family restrictions are explicit and are not silently folded into unrelated global authority.

Every primary claim-bearing session must have a campaign-rooted presentation-correlation artifact. Each session needs at least 30 correlated opportunities, a display opportunity for every correlation, no uncorrelated visual generations, and an accepted presentation-calibration status. The analyzer bridge rereads these files and verifies their hashes, counts, session identities, and calibration status set against the validity artifact.

The controller also rereads every Primary session's `native.complete.json` or `oxide.complete.json`, verifies its hash against the session result, and persists the envelope's input scope and validation status. Authoritative input requires the reserved final scope `trusted-os-input-plus-declared-application-stimuli` and a hash-bound complete raw-application-receipt manifest for every Primary session. The Rust controller derives each session's expected commands from its exact preflight pack and timing overlay, reproduces iteration expansion and scenario-global event indexes, validates the canonical Swift request/controller/application triplets, and records `complete-canonical-request-controller-application-v1` with a campaign-relative manifest identity. Analyzer publication rereads the manifest, requires the exact raw filename set, and rehashes every request/controller/application file so post-reduction deletion or tampering fails closed. Current Swift envelopes still use `direct-callback-diagnostic`, so the independent scope half of the gate remains false even when every receipt is complete. Unsupported preflight operations also continue to fail before launch.

Trace-overhead and external-sensor gates use the same independently reduced `instrumentation.calibration.json` identity. Full acquisition requires canonical trace-on/off input before GUI validation, build inspection, or session work; the controller requires the macOS Apple-silicon role, exact `Animation Hitches` template, at least 1 kHz sensing, 8–24 balanced pairs, alpha no greater than 0.05, and accepted p50, p95, and CPU margins. It persists and rereads the deterministic report, verifies the evidence hash again at final validity reduction, and the analyzer rehashes the report before publication. Correctness and qualification scopes remain runnable without this evidence. Common-GPU identities are recorded only when real session evidence exists; absence is an empty list, never invented evidence.

## Authority boundary

Campaign report schema 4 contains the hash-bound validity artifact identity. Full acquisition, calibrated-static correctness, exact pair/environment identity, the Section 9 CPU/wakeup ceiling, stable surface/power/thermal observations, and the non-environment validity gates must pass before the report can be globally authoritative. Metric-family availability remains narrower: a globally authoritative report still cannot publish comparable device-GPU, display-sensitive, interaction-sensitive, or short-run energy-equivalence claims when its corresponding family flag is false. The analyzer bridge validates this artifact before inspecting or publishing analyzer rows, including rereading the complete envelope and any declared raw-receipt manifest from the owning session directory.

## Performance

Environment commands and reduction run in the controller before each pair or outside measured acquisition. They do not execute in either measured application. The ten-second observer completes before either side launches, so its own CPU and filesystem work cannot enter a measured phase.
