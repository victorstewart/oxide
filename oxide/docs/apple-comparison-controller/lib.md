# `oxide-apple-comparison-controller`

## Intention and purpose

This non-publishable crate owns host-side Apple comparison orchestration. It keeps AB/BA planning, process launch, fixed-cadence process resource sampling, Instruments wrapping, presentation-trace correlation, deadlines, resume state, artifact validation, and source-boundary enforcement outside Oxide production hosts and libraries.

Timed-session admission independently reopens the envelope-bound telemetry coverage artifact, validates its deterministic path and SHA-256, and reconciles all coverage counts and availability states against the integrity-protected binary ring. Correctness sessions must not contain timed coverage.

## Relation to the rest of the code

The controller consumes the framework-neutral `oxide-benchmark-spec` acquisition, the exact plan bytes, and the identity manifest produced by `compare-ui build`. It launches only the dedicated binaries under `host/apple-comparison`; those binaries persist generation-bound evidence which the controller validates before writing a host-owned campaign report.

Call flow:

- `xtask compare-ui run`
  - `oxide_apple_comparison_controller::run_macos_campaign`
    - validate plan, acquisition, and Release product identities
    - `build_macos_campaign_plan`
    - launch or resume each isolated comparator session
    - sample exact-process CPU, memory, disk, instruction, cycle, and exposed energy counters
    - acquire standalone exact-PID Time Profiler or System Trace attribution passes without combining invasive templates
    - acquire the release energy pass from a calibrated direct external meter with no profiler or resource sampler
    - correlate comparison signposts through process-scoped Hitches updates and swap IDs to compositor frame-lifetime intervals
    - validate durable artifact, acknowledgement, resource, and controller-receipt identities
    - atomically persist `campaign.complete.json`

## Entry points list

- `build_macos_campaign_plan(acquisition: &ApplePrAcquisitionSpec, run_id: &str, plan_sha256: &str) -> Result<MacOsCampaignPlan>` derives the analyzer seed from the exact plan content and expands correctness plus all four seeded ABBA-or-BAAB presentation and launch pairs.
- `materialize_macos_analyzer_bundle(campaign_root: &Path, analyzer_plan_path: &Path, output_root: &Path) -> Result<MacOsAnalyzerBundleManifest>` converts one completed authoritative pass/pack into the generic analyzer's atomic plan/session/raw bundle; see [analysis_bridge.rs](analysis_bridge.md).
- `MACOS_RESOURCE_METRIC_SOURCE_PREFIX`, `MACOS_LAUNCH_METRIC_SOURCE_PREFIX`, `MACOS_COMMON_GPU_METRIC_SOURCE_PREFIX`, and `MACOS_ENERGY_METRIC_SOURCE_PREFIX` identify the bridge's validated non-presentation source families without admitting unproven aliases or proxy energy.
- `collect_macos_environment_snapshot`, `collect_macos_background_observation`, and `collect_macos_pre_pair_environment` acquire controller-owned endpoint and exact pre-pair validity evidence; see [acquisition_validity.rs](acquisition_validity.md).
- `macos_environment_policies`, `reduce_macos_acquisition_validity_with_pre_pair_environment`, `reduce_macos_acquisition_validity`, and `validate_macos_acquisition_validity` freeze schema-owned exact/tolerance/record-only policies, reduce claim-family availability, preserve a fail-closed compatibility reducer, and revalidate persisted evidence.
- `run_macos_campaign(config: &MacOsCampaignConfig) -> Result<MacOsCampaignReport>` executes or resumes the bounded macOS campaign.
- `run_macos_density_sessions(config: &MacOsDensitySessionConfig) -> Result<Vec<MacOsDensitySessionResult>>` executes ordered real unprofiled Primary AppKit/Oxide sessions without entering the authoritative campaign or invoking `xctrace` and binds each session to the verified build, plan, executable, resources, telemetry, and hashes.
- `validate_macos_gui_lock_ioreg(bytes: &[u8]) -> Result<()>` admits only explicit `IOConsoleLocked = false` evidence and fails closed on locked, missing, malformed, or non-UTF-8 state.
- `validate_macos_recapture_admission(config: &MacOsCampaignConfig, campaign: &MacOsCampaignPlan) -> Result<()>` permits correctness recapture but rejects qualification or full acquisition before application launch when any selected scenario checkpoint is marked for recapture.
- `reduce_apple_correctness_evidence(...) -> Result<AppleCorrectnessVisualReport>` computes the canonical exact-static matrix after validating plan, scenario, layout, screenshot path, and screenshot hash identities.
- `compare_apple_correctness_evidence(...) -> Result<AppleCorrectnessVisualReport>` uses that same controller-owned reducer and durably writes a standalone report for the CLI.
- `macos_campaign_sessions_for_scope(plan: &MacOsCampaignPlan, scope: MacOsCampaignScope) -> Vec<&MacOsCampaignSession>` selects either the four untimed correctness sessions or the complete twenty-session PR campaign without changing the frozen plan.
- `validate_macos_build_manifest(path: &Path) -> Result<()>` validates the complete Release build, toolchain and declared identity fields, executable bytes, and every file in both declared application bundles without launching either application.
- `validate_macos_build_input_identity(build_manifest_path: &Path, plan_path: &Path) -> Result<()>` additionally recomputes the comparison source tree and the exact specification tree containing the requested plan and rejects either tree when it differs from the build manifest.
- `comparison_tree_manifest(root: &Path, exclude_build: bool) -> Result<(String, u64, u64)>` is the single tree-identity implementation shared by `compare-ui build` and campaign admission; source identity excludes only the top-level comparison `build/` directory while specification and bundle identities include every entry.
- `validate_macos_appkit_comparator_admission(plan_path: &Path) -> Result<()>` selects the exact macOS/AppKit/native.production audit bound by the Apple plan and applies strict independent-review admission before full acquisition.
- `validate_macos_pair_shape(first: &MacOsCampaignSession, second: &MacOsCampaignSession) -> Result<()>` requires each acquisition boundary to contain two opposite implementations with the same chunk, pass, pack, pair, and timeout identity.
- `macos_session_arguments(plan: &MacOsCampaignPlan, session: &MacOsCampaignSession, output_root: &Path) -> Vec<String>` creates the complete immutable app invocation.
- `macos_session_generation(plan: &MacOsCampaignPlan, session: &MacOsCampaignSession) -> String` derives the deterministic session generation.
- `macos_application_bundle(executable: &Path) -> Result<PathBuf>` resolves only an exact `Contents/MacOS` executable to its containing application.
- `macos_process_id_from_ps(executable: &Path, output: &str) -> Result<Option<u32>>` parses an anchored exact-executable process identity.
- `audit_comparison_source_boundary(workspace_root: &Path) -> Result<()>` proves required comparison crates exist and campaign-specific markers are absent from production source roots.
- `compile_macos_trusted_input_trace(events: &[TraceEvent]) -> Result<MacOsTrustedInputPlan>` classifies declarative trace events into faithfully synthesizable XCUI commands and separately declared application stimuli; see [trusted_input.rs](trusted_input.md).
- `validate_macos_presentation_trace_bundle(path: &Path) -> Result<()>` rejects empty or unfinalized Instruments document shells before XML export or session resume.
- `validate_macos_trace_exports(toc: &str, signposts: &str) -> Result<()>` requires the concrete signpost, process-update, and frame-lifetime schemas plus all three comparison marker families.
- `reduce_macos_time_profiler_trace(time_profile_xml: &str, signposts_xml: &str, exact_pid: u32) -> Result<MacOsTimeProfilerArtifact>` reduces the isolated Time Profiler pass into exact-PID measured-phase CPU attribution; see [time_profiler.rs](time_profiler.md).
- `validate_macos_comparator_qualification_plan(...)` and `reduce_macos_comparator_qualification(...)` enforce the content-addressed all-release-scenario 1x/2x and bounded-profile contract; see [comparator_qualification.rs](comparator_qualification.md).
- `correlate_macos_presentation_trace(signposts_xml: &str, updates_xml: &str, frame_lifetimes_xml: &str) -> Result<MacOsPresentationCorrelationArtifact>` produces a fail-closed comparison-only correlation artifact; see [trace.rs](trace.md).
- `reduce_macos_system_trace(signposts_xml: &str, thread_info_xml: &str, thread_state_xml: &str, context_switch_xml: &str, pid: u32) -> Result<MacOsSystemTraceSummary>` reduces the standalone exact-PID scheduler attribution pass; see [system_trace.rs](system_trace.md).
- `MacOsDeepAttributionCollector` and `reduce_macos_deep_attribution_exports(...)` acquire and reduce one isolated Allocations, VM Tracker, Metal System Trace, or available GPU-counter replay; see [deep_attribution.rs](deep_attribution.md).
- `reduce_macos_energy(raw: &MacOsExternalMeterRawArtifact, calibration: &MacOsEnergyCalibration, telemetry: &[u8]) -> Result<MacOsEnergySummary>` reduces the isolated 120-second measured energy window and phase rows; see [energy.rs](energy.md).
- `validate_macos_launch_evidence(evidence: &MacOsLaunchEvidence, expected: &MacOsLaunchExpectation) -> Result<()>` rejects prepared-app and post-ready trace evidence; see [launch.rs](launch.md).
- `ComparisonSide`, `MacOsCampaignSession`, `MacOsCampaignPlan`, `MacOsCampaignConfig`, `MacOsCampaignSessionResult`, `MacOsPairCheckpoint`, and `MacOsCampaignReport` expose the controller's typed plan, atomic pair, and result boundaries. Each non-launch session result records the reopened surface-receipt path and SHA-256 validated against its completion envelope.

## Logic narrative

Planning preserves the committed controller-chunk order. The schema-2 materialized plan records the decimal seed derived from the first 64 bits of the exact source-plan SHA-256. The benchmark-spec-owned xorshift64 contract expands that seed in deterministic four-pair ABBA or BAAB blocks; A is the native reference and B is the Oxide contender, matching the analyzer. Every materialized session records the analyzer-compatible `ab` or `ba` value, and pair validation requires the two sides to execute in the declared order. Correctness runs both packs once per side without timing under the same deterministic order contract. Before GUI validation, build inspection, plan expansion, or app launch, Full scope independently reduces its canonical `--instrumentation-calibration` input, requires accepted trace-on/off sensor and CPU margins, and persists one report identity used by both instrumentation validity gates. Before plan expansion or any app launch, every campaign recomputes the same comparison-source and specification-tree identities recorded by `compare-ui build`; source or plan/specification drift fails closed even when product bundles still match their recorded hashes. Correctness-only scope may operate while a comparator audit or instrumentation calibration is unavailable so architecture work can acquire diagnostic pixels. Qualification-only scope executes the complete frozen session sequence without comparator admission or required instrumentation calibration solely to produce bounded audit and calibration evidence; its report remains non-authoritative by construction. Full scope first selects the exact macOS/AppKit/native.production audit from the plan and requires complete independent admission. After both correctness sides validate, the controller reduces every checkpoint with the calibrated static visual contract, persists `pair.correctness.json`, and binds its SHA-256, acceptance, counts, and full matrix into schema-2 `pair.complete.json`. Resume recomputes the matrix from current evidence. A Stage-1 correctness-only run finishes and reports acquisition completion independently from matrix acceptance. Qualification-only and full scopes cannot enter their first measured pair unless every correctness pack is present and accepted. `correctness_eligible_for_measured_acquisition` describes only this visual gate; `authoritative_eligible` remains false while required environment, presentation calibration, or measured-input evidence remains ineligible. Primary sessions now bind complete raw application receipt manifests, but current `direct-callback-diagnostic` envelopes still fail the independent final-scope requirement. Schema-1 pair checkpoints are never overwritten: explicit resume can recover complete side evidence into `pair.complete.v2.json`, leaving the old checkpoint intact. The rest of the paired launch, identity, resource, trace, and fault semantics remain unchanged.

Generic nightly and release expansion selects the exact pass timing overlay for each pack and persists its scenario subset into both sides of every session. Session deadlines are computed from the declared reset, readiness, setup, warmup, and duration-or-iteration occupied-time fields rather than from the PR-duration scenario manifests. Pair validation includes timing identity, so opposite sides cannot run asymmetric phase contracts.

Before a non-launch measured or attribution session resolves or starts its comparator process, the controller verifies the selected scenario and trace hashes and compiles every trace through the trusted macOS input capability boundary. Click, wheel, composer text, matching key-pair, and single-pointer drag operations are admitted; application-owned stimuli remain explicitly separate. Pinch/multipointer, pointer cancellation, IME composition, and exact text selection or replacement fail with a capability-specific reason before resource sampling or Instruments collection. See [trusted_input.rs](trusted_input.md).

After that preflight, every non-correctness measured session launches through the verified `MacOSComparisonControllerUITests` build-for-testing artifact rather than `/usr/bin/open`. The controller still discovers and samples the exact comparator PID, while the UI-test process services the durable trusted-input handshake and owns final application termination. Untimed correctness retains its direct launch because it applies deterministic trace state without claim-bearing input timing.

Before reading or revalidating live campaign evidence, the controller first requires the kernel-published `IOConsoleLocked` property to be explicitly false and then proves that macOS exposes a non-loginwindow foreground application. A locked, unknown, or unavailable GUI session therefore fails before any headed process can launch. A `caffeinate` child tied to the controller PID then owns display-idle and system-idle assertions for exactly the campaign lifetime; RAII termination prevents a stale assertion after every success or error path. Measured and qualification scopes reject configurations that disable this validation. Correctness-only offline checkpoint tests may disable it so a deliberately malformed checkpoint can be validated without a GUI session; the live CLI never does.

The controller forces `xcrun` through the native arm64 slice and requires the bounded `Animation Hitches` minimal-presentation template for every full campaign. It adds `os_signpost` to that template but does not add a second `Hitches` instrument; the template already owns the Hitches instrument, and duplicating it can leave an unfinalized Instruments document shell. A one-shot Darwin waiter is registered before xctrace starts, xctrace posts its supported tracing-started notification, and measured work cannot begin until that barrier succeeds while the recorder remains alive. The recorder safety limit spans the complete occupied-session ceiling rather than ending at the workload budget, so durable completion cannot race the recorder deadline. Once the workload and resource collection finish, the controller stops the exact attached app, verifies its exit, and sends xctrace one graceful interrupt before waiting for finalization. Normal recorder exit must leave a nonempty `form.template`, `corespace`, `instrument_data`, and `shared_data`; incomplete Instruments document shells fail before export and remain non-resumable. The controller then exports the TOC, signposts, process updates, and frame lifetimes. The trace correlator resolves Apple's reference-heavy XML, matches each visual generation to its generation-minus-one input marker, selects the containing or first following exact-process update, and joins that update to exactly one same-display frame lifetime by swap ID. Visual generations superseded before a unique update remain explicit uncorrelated rows. A session becomes resumable only after its complete envelope, durable acknowledgement, resource artifact, controller receipt, all trace exports, and the correlation artifact validate against the frozen run, generation, PID, and executable identity. Resume validation revalidates the finalized trace bundle, recomputes the artifact from its XML, and requires every row's formatted process identity to end in the controller PID. The controller receipt and public session result both carry the resource artifact SHA-256; the public result separately hashes every trace export and the correlation JSON.

Generic attribution sessions select exactly one collector. A System Trace session suppresses both Animation Hitches and Time Profiler, attaches the standalone `System Trace` template to the exact launched PID, and reduces only the unique main thread inside measured phase boundaries. Every `xctrace record` and `xctrace export` child receives an isolated controller-owned `TMPDIR`, `TMP`, and `TEMP`; recorders additionally own process-group teardown and a 512 MiB bundle-plus-scratch fuse. Because current `xctrace` can ignore those variables for root-level `instruments*.ktrace` work files, the controller fails closed if any such file pre-exists, includes newly created root spills in the same live fuse, and removes them on every success, error, and drop path. The finalized raw System Trace remains available for attribution while scratch and export working files are removed.

The release energy session is separately isolated from Instruments, screen recording, debug transport, common-GPU collection, and process-resource sampling. It requires a content-addressed direct external-meter adapter and complete calibration metadata, waits for hardware readiness before the start boundary, stabilizes for exactly 120 seconds, then measures exactly 120 seconds. Missing meter configuration produces explicit unavailability and no claim. Resume recomputes phase-bound joules and watts from the durable raw samples and comparator telemetry.

An `attribution-time-profiler` session replaces that presentation recorder with one isolated `Time Profiler` template plus `os_signpost`; the two templates are never combined. It uses `/usr/bin/arch -arm64 xcrun`, a separate session-owned trace and scratch path, and the same aggregate 512 MiB live fuse/finalization cleanup. The controller exports TOC, `time-profile`, and `os-signpost`, reduces exact-PID samples into measured scenario/phase intervals, persists weighted total/main-thread/top-stack attribution, and repeats the reduction during resume admission.

## Preconditions and postconditions

Run IDs are bounded path-safe identifiers. Plan, build, executable, bundle, source/specification, and predecessor-pair hashes are canonical lowercase SHA-256; the Git object ID is canonical SHA-1 or SHA-256 hexadecimal. The build must be Release arm64 macOS, contain exactly the expected AppKit and Oxide schemes, and retain nonempty toolchain identities and nonempty `.app` bundles whose executables remain under `Contents/MacOS`. Measured resource streams must contain at least two strictly time-ordered samples, cover PID discovery through durable application completion, retain one process UUID/start time, and keep cumulative counters monotonic. Success guarantees every selected session belongs to a validated two-side boundary, every pair has a durable hash-chained checkpoint, all expected process sessions have matching evidence, and the controller report has been synchronized and atomically renamed.

## Edge cases and failure modes

Missing or duplicate products, unexpected schemes, blank toolchain identities, changed comparison-source or specification trees, changed executable or application-bundle files, malformed hashes, executables outside their declared bundles, unknown packs, pending recapture metadata on a selected measured scenario, out-of-range or asymmetric pairs, partial one-side pair state, changed predecessor checkpoints, stale artifacts, non-durable acknowledgements, missing or invalid measured resource streams, PID reuse, counter rollback, nonzero process exits, trace-start notification failures, timeouts, oversized, empty, or unfinalized trace bundles, missing concrete Hitches/System Trace schemas, unresolved XML references, ambiguous process updates, missing or non-unique swap joins, main-thread identity mismatch, and incomplete scheduler coverage all fail closed. Existing pair checkpoints, trace paths, and exports are never overwritten.

## Concurrency and memory behavior

The controller intentionally launches one process at a time to preserve paired order and avoid measurement interference. One controller thread samples the exact process every 50 ms for latency/CPU/GPU attribution or every second for idle/endurance/memory/footprint passes, and is synchronously joined on success or failure; energy suppresses that sampler. A standalone System Trace pass adds one 100 ms storage-fuse monitor which owns no app state and terminates the complete recorder process group on failure. Campaign metadata is bounded by the selected validated plan.

## Performance notes

This crate is not linked into production and runs outside measured application code. Resource sampling and Instruments capture are isolated from correctness sessions. Their overhead remains subject to calibration before Stage 2 claims; `RUSAGE_INFO_V4` energy fields are persisted as raw exposed counters and are not substituted for required direct energy acquisition. Frame-lifetime interval ends and inferred signpost-to-update selection remain explicitly calibration-pending and are not labeled on-glass presentation times.

## Feature flags and cfgs

None.

## Testing and benchmarks

`tests/lib_tests.rs` freezes the twenty-session expansion, content-derived seed, seeded four-pair ABBA/BAAB order, analyzer-compatible session order evidence, complete invocation identity, full application-bundle build admission and mutation rejection, path/hash rejection, concrete trace-schema gate, and production-source boundary. `tests/trusted_input_tests.rs` freezes supported trusted command compilation, separate application-stimulus classification, and explicit rejection of unrepresentable input; see [trusted_input_tests.rs](tests/trusted_input_tests.md). `tests/trace_tests.rs` covers XML reference inheritance, generation matching, process/update selection, exact duplicate-row normalization, missing display markers, superseded generations, ambiguity, and swap joins. The boundary permits only the named benchmark/spec/snapshot/test-scene crates under `crates`; all shipping crates and production host roots remain forbidden.

## Examples

Use `cargo xtask compare-ui run --platform macos --plan benchmarks/comparative/specs/v1/plans/apple-pr.json --build-manifest /tmp/oxide-comparison-build-macos.json --out /tmp/oxide-macos-correctness --run-id mac-correctness-001 --correctness-only` for a fresh Stage-1 visual qualification. Add `--resume` only when intentionally validating existing atomic pair checkpoints. Omit `--correctness-only` only when the global harness gate permits the full acquisition campaign.
